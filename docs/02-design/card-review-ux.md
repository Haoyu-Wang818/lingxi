# 卡片式复习设计建议（手机优先，手表做推送）

> 结论先行：手机端借鉴市面背单词 App 成熟的「一屏一卡、先回忆后翻面、三键自评」，差异化放在**卡片背面的课堂溯源与知识图谱上下文**；手表只做「一条通知 = 一道 3 秒能答完的题」，作答两键、不翻长答案、忽略不算遗忘。

## 1. 市面产品怎么做

| 产品 | 卡片正面 | 作答与自评 | 节奏 | 激励 | 值得借鉴 |
| --- | --- | --- | --- | --- | --- |
| 墨墨背单词 | 单词 + 音标 | 认识 / 模糊 / 忘记 三档，看释义后可改判「记错了」 | 每日新词量可调，首页显示今日剩余，到期复习优先 | 签到日历、学习统计 | 三档自评对中国学生最熟悉；看完答案允许纠正自评 |
| 百词斩 | 单词 + 四张图 | 四选一图选义，系统自动判对错；「斩」掉已会的词 | 按组推进，组末回顾 | 打卡海报、分享 | 客观题自动判分，免去自评负担；一键排除已掌握内容 |
| 不背单词 | 单词 + 真实语境例句（影视原声） | 认识 / 不认识，再看释义自检 | 每组若干词，组内错词回炉 | 打卡 | 用「真实出处」帮记忆，对应我们的课堂溯源 |
| Anki | 自定义正面 | 显示答案后 重来 / 困难 / 良好 / 简单 四键，按钮上直接显示下次间隔 | 到期队列 + 新卡上限；已内置 FSRS | 几乎没有 | 按钮上显示「下次 2 天后」，让间隔重复可感知 |
| Quizlet | 术语，点击 3D 翻面 | 左右滑分成「还在学 / 已掌握」两堆 | 一轮结束只重练没掌握的 | Match 计时小游戏、进度条 | 滑动手势单手好用；翻面动画有仪式感 |
| 多邻国（激励参考） | — | — | 每日目标很小 | 连胜天数 + 冻结卡、联赛 | 连胜冻结卡降低「断签就放弃」 |

共性：**一屏一卡、主动回忆、自评驱动调度、短组推进、可见的每日剩余量**。差别主要在卡片内容（图、例句、自定义）和激励强弱。

## 2. 手机端卡片设计

### 2.1 卡片布局

```
┌───────────────────────────────┐
│ 高等数学 · 泰勒展开      3/8  │  课程 + 知识点 + 组内进度
│                               │
│   sin x 在 x=0 处的三阶       │  问题：大字，居中
│   泰勒展开是什么？            │
│                               │
│        轻点翻面 · 先想一想     │
└───────────────────────────────┘
          ↓ 翻面
┌───────────────────────────────┐
│ x − x³/6 + o(x³)              │  答案：一句话
│ 一两句解释（KnowledgePoint     │
│ .summary）                     │
│ ─────────────────────────     │
│ 📷 11月18日 板书 第3页  ▸      │  课堂溯源：点开看原始板书 / 录音片段
│ 前置：导数定义  · 相关：麦克劳林 │  图谱邻居，点开进入图谱
│                               │
│ [忘了 10分]  [模糊 1天]  [记得 4天] │  按钮显示 FSRS 预测的下次间隔
└───────────────────────────────┘
```

差异化要点：背单词 App 的背面是释义和例句，我们的背面是**「这张卡来自哪堂课、和哪些知识点相连」**。这直接展示了「课堂内容到知识图谱」这个创新点，评委一眼能看出不是普通背单词 App。

### 2.2 交互

- **先回忆再翻面**：正面不放任何答案线索，轻点翻面（带翻转动画）。不用「滑动揭示」，避免用户不想就翻。
- **三键自评**：忘了 / 模糊 / 记得，分别对应 `Rating.AGAIN / HARD / GOOD`；在卡片上**上滑**为「太简单」= `EASY`，不占按钮位。三档比 Anki 四键更容易用对，FSRS 社区也建议拿不准时只用「重来」和「良好」，乱用困难/简单反而会让算法变差。
- **单手手势**：左滑 = 忘了，右滑 = 记得（Quizlet 式），按钮仍保留给不熟悉手势的人。
- **客观题自动判分**：判断题、单选题答完系统直接判，答错 = AGAIN，答对 = GOOD；答对后给一个小按钮「其实是蒙的」改为 HARD（借鉴墨墨的「记错了」）。
- **撤销上一张**：误触是卡片 App 最高频的投诉，顶部保留撤销。

### 2.3 节奏

- **每日任务 = FSRS 到期卡 + 新卡**。新卡默认每天 10 张，可调；首页写「今日 23 张，约 6 分钟」，用时长而不是张数降低心理负担。
- **短组推进**：每组 5–8 张，组末给一屏小结。碎片时间由情境引擎决定组大小（排队 30 秒 = 3 张，通勤 = 一整组），把「碎片时间情境引擎」落到用户看得见的地方。
- **组内回炉**：本组答「忘了」的卡在组末再出现一次，不重复计入 FSRS 评分（同日重复只更新短期步进）。
- **新卡先学后测**：新知识点第一次出现先展示正反面与来源，第二次才进入测验。
- **积压保护（图谱感知排序，创新点）**：到期卡积压超过 50 张时，先排前置知识点、再按可提取性从低到高；如果前置点答了「忘了」，把依赖它的后续卡顺延到下一组。这是背单词 App 做不到的，因为单词之间没有先修关系。

### 2.4 让间隔重复「看得见」

- 自评按钮上显示下次间隔（Anki 做法）。
- 知识图谱节点按可提取性着色（绿 / 黄 / 红），形成「记忆热力图」，点红色节点可以直接复习那一簇。
- **考前模式**：录入考试日期后，把该课程的目标保持率从 0.90 提到 0.95，并把考试日之后才到期的卡提前，首页显示「距期中 12 天，高数待巩固 34 个知识点」。

### 2.5 激励（对大学生要克制）

- 保留：连续天数 + 每周 1 张「冻结卡」、日历热力图、完成页总结（「本次巩固 12 个知识点，高数掌握度 +4%」）、图谱节点被逐渐点亮。
- 不做：积分商城、全网排行榜。大学生反感幼稚化，也不想被比较。可以留一个同课程小组的可选打卡作为加分。

## 3. 手表端：一条通知 = 一道题

### 3.1 定位

手表的价值是「不掏手机就能收到并完成复习」。所以手表端不是缩小版手机 App，而是**带作答按钮的通知**，外加一个显示今日待复习数的磁贴（Tile）。

### 3.2 内容规则

| 规则 | 建议值 | 原因 |
| --- | --- | --- |
| 题型 | 只推 `fitsWatch = true` 的判断题、二选一，和答案很短的回忆题 | 3 秒内能作答 |
| 问题长度 | ≤ 20 个汉字（圆屏约 3 行） | 不滚动就能读完 |
| 答案长度 | ≤ 12 个汉字；更长的不推到手表 | 手表上不翻长答案 |
| 按钮 | 只有 2 个，大按钮（≥ 48dp） | 抬腕单指操作 |
| 每次推送 | 1 张，答完可「再来一张」，最多连续 3 张 | 30 秒内结束 |
| 反馈 | 作答后震动 + ✓ / ✗ + 一行正确答案，1.5 秒后自动收起 | 不需要再点关闭 |
| 频率 | 每天 ≤ 6 次；上课、睡眠、运动中不推 | 由情境引擎和课表把关 |

### 3.3 三种手表卡

```
 判断题                二选一                短回忆题
╭──────────────╮    ╭──────────────╮    ╭──────────────╮
│  高数 · 极限  │    │  数据结构     │    │  英语 · 词汇  │
│ 可导一定连续？│    │ 栈的特点？    │    │  ubiquitous  │
│              │    │              │    │  轻点看答案   │
│ [ ✓ ]  [ ✗ ] │    │[先进后出][先进先出]│ │ [忘了] [记得] │
╰──────────────╯    ╰──────────────╯    ╰──────────────╯
```

- 判断题和二选一自动判分：答对 = GOOD，答错 = AGAIN。
- 短回忆题：轻点显示答案（一行），再选「忘了 / 记得」，只映射 AGAIN / GOOD，手表上不提供 HARD / EASY。
- **忽略或「稍后」不算遗忘**：只是把这次推送顺延，不写入 FSRS，避免没看手表被当成没记住。

### 3.4 卡片需要一个「手表版本」

课堂卡片的问题和答案往往偏长。建议在生成卡片时，让大模型同时产出一个压缩版本，并像知识抽取一样做长度校验：

```kotlin
data class ReviewCard(
    // ……现有字段
    val watchPrompt: String? = null,  // ≤ 20 字，为空则不推到手表
    val watchAnswer: String? = null,  // ≤ 12 字
)
```

校验不过就置空，这张卡只在手机上出现。这样「手表内容一定不能多」变成可测试的规则，而不是靠人工把关。

### 3.5 分两步做

1. **初赛（P1–P2）基于 Wear OS Data Layer**：初赛不要求真机展示，手机与手表模拟器之间用 Data Layer 同步卡片和作答结果，手表端直接做独立的卡片界面 + 磁贴「今日待复习 8 张」，手机首页提示「已在手表复习 3 张」。
2. **进入决赛再适配真机**：Data Layer 依赖 Google Play 服务，国内 OPPO 手机没有。届时向官方确认可用的手表型号和同步方式（例如厂商 SDK 或手表直连网关）。为了到时少改代码，同步逻辑放在一个接口后面（例如 `WatchSync`），Data Layer 只是它的一个实现。

## 4. 给开发计划的改动清单

1. `core:model`：`ReviewCard` 增加 `watchPrompt` / `watchAnswer`；增加 `sourceRef`（板书页、录音时间点）用于背面溯源。
2. `core:review`：提供「预测四档下次间隔」接口给按钮显示；增加图谱感知的到期队列排序；同日重复不重复计分。
3. `app`：卡片页（翻面、三键、上滑太简单、左右滑、撤销）、组末小结、首页「今日 N 张约 M 分钟」、考前模式。
4. `wear`：基于 Data Layer 的手表卡片页（两键作答）和磁贴，同步逻辑封装在 `WatchSync` 接口后。
5. `server`：卡片生成时同时产出手表压缩版并做长度校验。
