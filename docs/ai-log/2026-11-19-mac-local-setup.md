# 2026-11-19 迁移到本地 Mac 开发并跑通模拟器

## 目标

按团队要求，所有开发和测试都在本地 Mac（Apple Silicon）上完成；确认是否需要安卓真机，搭好本地环境并在模拟器上跑通手机与手表。

## 关键提示与决策

- 调研结论：开发和大部分测试可以只用模拟器；续航、真实传感器、端侧大模型性能留到真机阶段验证。
- 国行手机通常没有 Google Play 服务，Wear Data Layer 不可靠。新增 `core:sync`：传输无关的消息协议、`WatchLink` 接口、
  主备双链路（按消息 id 去重），并在网关上加 WebSocket 中继 `/v1/relay/{pair_code}/{role}`。
- OCR 改为 PP-OCR 模型转 ONNX，用 ONNX Runtime 运行（Paddle-Lite 官方示例较旧）。
- 去掉 GitHub 云端 CI，全部本地构建测试。
- 依赖升级到当前稳定版：Gradle 9.9.1、Kotlin 2.4.21、AGP 9.5.1（内置 Kotlin 支持）、compileSdk 37、JUnit 6。
- 模拟器问题排查：终端的代理变量会被模拟器内部的 netsimd 继承，把模拟器内所有 TCP 连接转给代理，
  手机模拟器因此连不上 `10.0.2.2` 上的网关，启动时也出现过卡死；崩溃一次后，启动时会弹出崩溃上报确认框导致后台启动卡住。
  `scripts/emulator.sh` 去掉代理变量并关闭崩溃上报后再启动。

## 产出

- `core:sync` 及 13 个测试；网关中继及 4 个测试
- 手机端新增「手表」联调页，手表端改为接收推送并回传作答结果
- 两个模拟器联调通过：手机端点「推送到手表」→ 手表显示卡片 → 手表作答 → 手机端显示作答结果和用时
