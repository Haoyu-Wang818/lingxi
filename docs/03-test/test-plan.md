## 1. 范围与目标

覆盖初赛 Beta 的全部 Must 需求（50 条）与相关非功能需求；所有测试在本地 Mac 上运行，不使用云端 CI。
目标：Must 需求 100% 有测试引用（`scripts/trace.py --check` 通过），核心 JVM 模块行覆盖率 ≥ 80%，初赛提交时无严重缺陷。

## 2. 测试层次

| 层次 | 对象 | 工具 | 运行命令 | 何时运行 |
| --- | --- | --- | --- | --- |
| 单元 | `core:*`、`context-engine`、网关 | JUnit 6、kotlinx-coroutines-test、pytest | `./gradlew test`、`uv run pytest` | 每次提交（pre-push 钩子） |
| 集成（Android 本地） | Room DAO 与仓库、网关客户端 | Robolectric、Room 内存库、MockWebServer | `./gradlew testDebugUnitTest` | 每次提交 |
| 迁移 | Room 迁移 | `MigrationTestHelper` | 同上 | 结构变更时 |
| 界面 | 今日、卡片复习、拍照、设置、手表卡片 | Compose UI Test（模拟器） | `./gradlew connectedDebugAndroidTest` | 每个迭代结束 |
| 端到端 | 拍板书 → 卡片 → 复习 → 推送 → 手表作答 | `scripts/e2e.sh`（adb 驱动两台模拟器、截图） | 手动触发 | 每个迭代结束 |
| 算法评测 | OCR 准确率、抽取质量、去重阈值 | `scripts/eval/*.py` + 自建数据集 | 手动 | I2、I4 结束 |
| 非功能 | 耗时、内存、耗电、断网 | Android Studio Profiler、飞行模式 | 手动 | 测试周 |

## 3. 需求到测试的映射规则

- 每个测试用 `@DisplayName("[FR-REV-07] 左滑记为忘了")` 或 pytest 的 docstring 首行写需求编号；`scripts/trace.py` 据此生成矩阵。
- 详细设计中的 `TC-*` 用例编号写在测试方法的 KDoc 中，便于从设计找到测试。

## 4. 测试数据

| 数据集 | 内容 | 用途 | 位置 |
| --- | --- | --- | --- |
| 板书照片 20 张 | 高数、大物、程序设计各若干，含斜拍、反光 | OCR 准确率、矫正 | `testdata/boards/`（只放自己拍摄或授权的图片） |
| 课堂录音 10 段 | 每段 5 分钟普通话 | 转写字错率 | `testdata/audio/` |
| 抽取样本 10 节课 | 识别文本 + 人工标注知识点 | 抽取准确率 | `testdata/extract/` |
| 去重标注 30 对 | 同义 / 不同义知识点名 | 相似度阈值调参 | `testdata/dedup.csv` |
| 大模型录制响应 | `/v1/extract`、`/v1/cards` 的 JSON | 网关与客户端测试，不调用真实接口 | `server/tests/fixtures/` |
| 情境回放 | 排队、通勤、上课、跑步、深夜的一天信号序列 | 情境引擎与推送预算 | `context-engine/src/test/resources/` |

匿名要求：测试数据中不得出现学校名称、教师和同学姓名。

## 5. 迭代测试安排

| 迭代 | 重点测试 | 出口标准 |
| --- | --- | --- |
| I1 数据层 | DAO、仓库、迁移、网关客户端、路由扩展（TC-AI-*） | 仓库层覆盖率 ≥ 80% |
| I2 拍板书到卡片 | OCR 评测、抽取与卡片校验（TC-KG-*、TC-QA-*）、整理流程界面 | OCR 字准确率 ≥ 90%；一张板书到卡片 ≤ 15 秒 |
| I3 卡片式复习 | 调度与队列（TC-REV-*）、卡片页手势与按钮界面测试 | 30 张卡片走完，状态与日志正确 |
| I4 录音与图谱 | 转写评测、去重阈值评测、图谱渲染帧率 | 字错率 ≤ 15%；100 节点 ≥ 30 帧 |
| I5 推送与手表 | 推送策略（TC-CTX-*）、情境回放、手表消息可靠性、Data Layer 与中继切换 | 静音时段 0 次推送；作答不丢不重 |
| 测试周 | 全量回归、端到端、非功能、匿名扫描 | 无严重缺陷；`trace.py --check` 通过 |

## 6. 缺陷管理

- GitHub Issues 记录，标签：`严重`（崩溃、数据丢失、演示主流程中断）、`一般`、`轻微`；附复现步骤与截图。
- 严重缺陷 24 小时内修复；01-09 功能冻结后只修缺陷。

## 7. 进入与退出准则

- 进入：需求与设计已评审；对应模块接口已在代码中定义。
- 退出（初赛提交）：Must 需求测试全部通过；无严重缺陷；测试报告 `docs/03-test/test-report.md` 已更新并附端到端截图。

## 8. 风险

| 风险 | 应对 |
| --- | --- |
| 模拟器上无法测真实传感器 | 情境回放数据 + 情境实验室手动注入 |
| 大模型输出波动导致测试不稳定 | 自动化测试只用录制响应；真实调用只在评测脚本中 |
| Data Layer 在模拟器配对不稳定 | 保留中继备链路测试；配对步骤写入 README |
